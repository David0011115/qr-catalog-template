# Подключение серверного онлайна Kapli-3D

Серверная часть подготовлена отдельно от основной игры. До подключения Cloudflare и Supabase она не создаёт Worker и не меняет удалённые ресурсы.

## Что уже подготовлено

- Cloudflare Worker и Durable Object `GameRoom` с SQLite-хранилищем.
- Комнаты на двух игроков, коды, готовность и трёхсекундный старт.
- Серверная симуляция, последовательности команд, подтверждения и WebSocket-снимки.
- Пауза при отключении и окно переподключения 30 секунд.
- Ограничение пяти неверных кодов комнаты на аккаунт с блокировкой на одну минуту — общее для всех введённых кодов.
- Восстановление состояния из SQLite snapshot и event log.
- Клиентский серверный режим в браузерной игре.
- Сохранение результатов через отдельные серверные Supabase RPC.
- Повторная отправка результата, если Supabase временно недоступен.

## 1. Supabase

1. Открой Supabase → SQL Editor.
2. Проверь, что уже применён `DUO-RECORDS-MIGRATION.sql` (в проекте должны существовать `kapli_duo_territory` и `kapli_duo_coop`). Если его ещё нет — сначала выполни этот файл.
3. Проверь, что применён `PRIVACY-CONSENT-MIGRATION.sql`: Worker вызывает RPC `kapli_has_privacy_consent()` до загрузки профиля и сохранения игрока. Если функции нет — выполни эту миграцию.
4. Затем выполни `ONLINE-SERVER-RESULTS-MIGRATION.sql` из этой папки проекта.
4. Убедись, что миграции завершились без ошибок.

`DUO-RECORDS-MIGRATION.sql` создаёт существующие таблицы статистики режимов для двоих и рейтинговые RPC. `PRIVACY-CONSENT-MIGRATION.sql` создаёт проверку согласия с политикой конфиденциальности. `ONLINE-SERVER-RESULTS-MIGRATION.sql` добавляет журнал серверных матчей и защищённые service-role RPC для записи только серверных результатов. Отдельная система рейтинга не создаётся; эти миграции подготовлены для повторного выполнения.

## 2. Подготовь Cloudflare secrets

Из папки `server/cloudflare` скопируй шаблон:

```sh
cp .env.example .env.production
```

Заполни четыре значения:

- `SUPABASE_URL` — URL проекта Supabase.
- `SUPABASE_ANON_KEY` — публичный anon/publishable key этого же проекта.
- `SUPABASE_SERVICE_ROLE_KEY` — service-role key. Он нужен только Worker для записи итогов; не вставляй его в браузер и не отправляй в репозиторий.
- `ALLOWED_ORIGINS` — точный origin сайта игры, например `https://game.example.com`. Без пути и завершающего слеша. Несколько origin можно перечислить через запятую.

Файл `.env.production` исключён из Git. Не снимай это исключение и не публикуй его содержимое.

## 3. Собери и разверни Worker

Требуется Node.js 22.18 или новее.

```sh
cd kapli-3d/server/cloudflare
npm install
npx cf auth login
npm run build
npm run deploy -- --secrets-file .env.production
```

`npm run build` только собирает и проверяет проект. `npm run deploy -- --secrets-file .env.production` создаёт/обновляет Worker и его Durable Object в выбранном аккаунте Cloudflare. Команда выведет адрес Worker.

Для локальной разработки создай локальный `.dev.vars` с теми же четырьмя переменными и запускай `cf dev`.

## 4. Подключи игру к Worker

1. Открой игру и выбери режим «Играть вдвоём».
2. В поле адреса Cloudflare Worker вставь URL, который выдал `cf deploy`, например `https://<worker>.<account>.workers.dev`.
3. Нажми «Подключить».
4. Войди в существующий аккаунт игры, создай комнату и передай пятисимвольный код второму игроку.
5. Оба игрока нажимают «Готов».

Адрес Worker сохраняется в браузере. Клиент использует уже существующую Supabase-сессию игры; второй Supabase-клиент или отдельная авторизация не нужны.

## 5. Проверка перед публикацией

Из корня `kapli-3d`:

```sh
node --test
```

Из `server/cloudflare`:

```sh
npm test
cf build
```

После развёртывания проверьте:

- `GET <worker-url>/health` возвращает `ok: true`.
- Создание и вход в комнату с двух аккаунтов.
- Готовность обоих игроков и старт матча.
- Territory: движение, захват, победа и запись результата.
- DuoBack: волны, боссы, выбор улучшений и совместное поражение/победа.
- Отключение одного игрока, паузу и восстановление в течение 30 секунд.
- Запись результата в Supabase и повторную отправку при временной ошибке.

## Важно

- Все изменения проекта находятся только в ветке `kapli-3d-online-test`.
- Ветка `main` не изменялась.
- Worker не развёртывался, Supabase migration не выполнялась, удалённые Cloudflare/Supabase ресурсы не менялись.
- До подключения и проверки Cloudflare/Supabase нельзя считать онлайн готовым к публичному запуску.
